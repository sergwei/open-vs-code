# Languages and translations

The extension follows the display language of VS Code. English is the base; Spanish (`es`) ships
with the extension. Adding another language is adding two files and no code.

## What the user needs

VS Code only reports a language other than English when the matching **language pack** is installed
(for Spanish, "Spanish Language Pack for Visual Studio Code" by Microsoft). Without the pack,
`vscode.env.language` is `en` even if the operating system is not, and the extension shows
English. This is a property of VS Code, not of the extension: setting `"locale"` in `argv.json`
with no pack installed gives English too.

Galician is not offered because no Galician language pack exists in the Marketplace or in Open VSX
(checked 04/11/2026), so VS Code can never report `gl`. The day a pack is published, adding
Galician is the two files described below.

## How it works

Three layers, each with its own catalog:

| Layer | What it translates | Catalog | Who reads it |
| --- | --- | --- | --- |
| Manifest | command titles, setting descriptions, view names, welcome texts | `package.nls.json` and `package.nls.<id>.json` | VS Code itself, replacing every `%key%` of `package.json` |
| Extension host | notices, dialogs, tree items, badges | `l10n/bundle.l10n.json` and `l10n/bundle.l10n.<id>.json` | `@vscode/l10n`, configured at boot |
| Webviews | chat and Settings tab | the same `l10n/` bundle | `@vscode/l10n` in the browser build, configured at boot |

Rules that make it work:

- **One call everywhere:** `import * as l10n from '@vscode/l10n'` and `l10n.t('English text', args)`.
  The English text is the key. In English no bundle is loaded and `t` returns the text itself, so
  the base bundle is generated and never edited by hand. When the English is ambiguous, use
  `l10n.t({ message, comment })` (the comment becomes part of the key). ESLint forbids
  `vscode.l10n` outside the boot file and named imports of `@vscode/l10n`, so the extractor always
  sees `l10n.t(`.
- **Placeholders, never concatenation:** `l10n.t('Removed {0}', name)`. A template literal with
  `${}` inside `t` makes the exporter fail, and gluing translated fragments breaks other languages.
  A sentence with a component inside uses `formatParts` from `src/shared/l10n.ts` with
  `{name}` placeholders.
- **Boot order:** `src/extension/l10nBoot.ts` is the first import of `extension.ts`, and
  `webview-ui/src/l10nBoot.ts` is the first import of `index.tsx`. VS Code loads the host bundle
  before it requires the extension, and the webview gets the language in `<html lang>` and the
  bundle in a `<meta name="open-vs-code-l10n">`, so even module-level constants are translated.
  `l10nCatalog.test.ts` fails if another import goes first.
- **Dates and numbers** follow the same language through `Intl`.
- **The prompt of Explain/Fix with OpenCode** is built in the language of VS Code, so the model
  answers in it.

## Adding a language

1. Find the `languageId` of the pack in lowercase: `es`, `pt-br`, `zh-cn`. VS Code looks the files
   up by exactly that id (the docs list the locales:
   https://code.visualstudio.com/docs/configure/locales).
2. Copy `package.nls.json` to `package.nls.<id>.json` and translate the values. Keep the keys, the
   order, the `(command:...)` links and the `#openVsCode....#` setting references.
3. Copy `l10n/bundle.l10n.json` to `l10n/bundle.l10n.<id>.json` and translate the values. Keep the
   keys, **in the same order**, and every `{0}`, `{name}` placeholder (a translator may reorder
   them inside the sentence, not drop one).
4. Run `npm run l10n:check`. It exits 1 with one line per problem: a missing or extra key, a
   changed placeholder or link, a different order, an empty value, a language with only one of the
   two files, or a base bundle that is out of date.
5. `npm test` runs the same check, so a half-translated language cannot be merged.

No list of languages lives in the code: they are discovered by file name. The packaged `.vsix` must
carry both files of each language; `scripts/check-vsix.mjs` checks the pairs.

When code texts change, run `npm run l10n:export` to regenerate `l10n/bundle.l10n.json`, then
update every language file (the check names what is missing). Changing an English text leaves its
translation orphaned: the check reports it.

## Limits

- **Plurals:** `plural(count, one, other)` in `src/shared/l10n.ts` picks between two forms with
  `Intl.PluralRules`. It covers languages with one/other (English, Spanish, Portuguese, German...).
  A language with a third form (few/many, as Polish or Russian) needs a new form in the code;
  that is not built.
- **Missing key:** the English text shows. The catalog check prevents it for the languages that
  ship.
- **Not translated on purpose:** the lines of the OutputChannel log and the names of the channels
  (`OpenCode`, `OpenCode Mods`), because support and the tests read them; error codes; the
  product name `OpenCode Station`; what comes from opencode or the model (messages, tool output,
  agent and model names, session titles); the text of mods and their panels; the test fixtures.
  A host text that is also logged (an error message, a detection detail) is built once with
  `bothTexts` / `translatedError` from `src/extension/l10nEnglish.ts`, which also keeps its English
  twin for the log; only that module may call `l10n.config` (an ESLint rule enforces it).
- Changing the display language of VS Code needs a restart, and so does the extension.

## Guide for translators

Glossary (Spanish), approved by the maintainer:

| English | Spanish |
| --- | --- |
| session | sesión |
| prompt | prompt (not translated; "el prompt") |
| message (what the user sent) | mensaje |
| permission | permiso |
| agent / model / server | agente / modelo / servidor |
| mod | mod (plural: mods) |
| revert / fork / compact | revertir / bifurcar / compactar |
| attach | adjuntar |
| archive / pin | archivar, desarchivar / anclar, desanclar |
| provider / workspace / folder / tab | proveedor / área de trabajo / carpeta / pestaña |
| send / stop / retry / remove | enviar / detener / reintentar / quitar |
| log | registro |
| API key / sign in | clave de API / iniciar sesión |
| settings | configuración (the screen); ajuste (one setting) |
| plugin, chat, panel | plugin, chat, panel |

**Tone:** follow the Spanish language pack of VS Code. The interface addresses the user as *usted*
("Abra", "Déjela vacía") and command titles use the infinitive ("Nueva sesión", "Poner el foco en
el prompt"). The prompts the extension sends to the model on the user's behalf (the suggestions of
the empty chat and the Explain/Fix prompt) are the exception: they use *tú* ("Explica qué hace
@a.ts"), because they are the user's own voice.

Practical rules for any language:

- Translate the meaning, not word by word; the placeholders move with the grammar.
- Keep the same terms for the same concept everywhere; start from the glossary and add your
  language's column.
- Spanish is 20-30 % longer than English. Buttons and menus must not overflow at 300 px wide;
  no automated test measures that for Spanish (the Spanish window of `test:visual` was removed on
  04/11/2026), so look at it by hand (see "Checking a language" below).

## Checking a language

- `node scripts/l10n.mjs check` (also run by `npm test`): both catalogs of every language have the
  same keys, placeholders and links as the base, and the `l10n/` bundle keeps the order of the
  base too.
- The unit tests that load the real Spanish catalog (`useSpanish`, `src/extension/test-fixtures/spanishCatalog.ts`)
  check the texts the host and the webview build from it.
- There is NO automated test in a VS Code that really runs in that language. To see overflow and
  the look, use a VS Code profile of its own, so that your everyday VS Code keeps its language:
  `Configure Display Language` writes the `argv.json` that every window of your user shares.
  Install the language pack in that profile, start it once (VS Code registers the pack on that
  first start) and then start it again with `--locale=<id>`. This is what the removed test did, on
  Windows 11 with VS Code 1.145.0 (04/11/2026); by hand, as written here, it is untested. Then open
  the chat at 300 px wide, the "+" menu, the agent and model panel, a permission card, the
  Settings tab and the command palette.
